\section{Publish nguyên tử}
\code{repositories.py:311-384}:
\begin{enumerate}
  \item Mỗi mart được ghi JDBC vào \code{staging.mp_<mart>_<sha256(run_id)[:16]>}.
  \item Trong \textbf{một} transaction có \code{pg_advisory_xact_lock}: kiểm lại số dòng, \code{TRUNCATE} cả 12 bảng \code{cache.*},
        \code{INSERT ... SELECT} từ staging, upsert \code{audit.marketplace_cache_version}.
  \item Người đọc chỉ thấy toàn bộ run cũ hoặc toàn bộ run mới.
\end{enumerate}

\section{Promote}
Stage \code{promote} so \code{run_id} trong \code{current.json} với \code{expected_current_run_id} đã ghi lúc tạo run (compare-and-swap).
Khớp thì ghi \code{current.json} = byte của manifest; lệch thì run thành \code{HELD} với \code{PROMOTION_CONFLICT}.
Một run có \code{as_of} cũ hơn run đang current chỉ được promote khi có \code{--allow-backfill}.
Thứ tự publish trước promote (ADR-0005) bảo đảm pointer không trỏ vào Gold mà cache chưa có.
