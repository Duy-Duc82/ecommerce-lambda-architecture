Tìm hiểu crawl dữ liệu Shopee và các sàn TMĐT

Yêu cầu: crawl trực tiếp trang web, không gọi API · Thử nghiệm 09/10/2026 · Python 3.12, Playwright 1.57 (Chromium)

1. Các cách tiếp cận đã thử

1HTTP request + parse HTML (server-side rendered)

Thư viện
urllib.request (tương đương requests), re, html
Cách làm
Gửi GET tới URL trang danh mục với header User-Agent Chrome, Accept-Language: vi-VN, giải nén gzip, rồi dùng regex/selector lấy tên, giá, URL sản phẩm trong HTML. Không thực thi JavaScript.
Điều kiện
Chỉ dùng được khi trang render dữ liệu phía server (SSR). Với SPA (client-side rendering), HTML trả về chỉ là khung rỗng.
# rút gọn
req = urllib.request.Request(url, headers={"User-Agent": UA, "Accept-Language": "vi-VN"})
html = urllib.request.urlopen(req, timeout=30).read().decode("utf-8")
prices = re.findall(r"\d{1,3}(?:\.\d{3})+\s*₫", html)

2Trích dữ liệu có cấu trúc nhúng trong HTML

Thư viện
re + json
Cách làm
Nhiều trang SSR nhúng sẵn state dạng JSON trong thẻ <script>. Tách khối đó ra bằng regex, json.loads(), rồi duyệt đệ quy tìm các object có id, name, price.
  • <script id="__NEXT_DATA__">: state của Next.js (Tiki)
  • <script type="application/ld+json">: JSON-LD schema.org Product/Offer (Thế Giới Di Động, Điện Máy Xanh, Lazada…)
Ưu điểm
Dữ liệu đầy đủ, đã có kiểu (giá là số nguyên). Ít phụ thuộc vào CSS class nên ít hỏng khi trang đổi giao diện.
m = re.search(r'<script id="__NEXT_DATA__"[^>]*>(.*?)</script>', html, re.S)
data = json.loads(m.group(1))
products = walk(data)   # lấy các dict có đủ khóa id, name, price

3Headless browser (Playwright)

Thư viện
playwright.sync_api, Chromium headless và headed
Cách làm
chromium.launch(headless=True) → page.goto(url, wait_until="domcontentloaded") → chờ JS render (wait_for_timeout) → mouse.wheel để kích lazy-load → đọc DOM bằng page.eval_on_selector_all(). Phân trang qua tham số ?page=N, delay 3–5 giây giữa các trang.
Selector
Lazada: [data-qa-locator="product-item"], lấy data-item-id, data-sku-simple, a[title], giá trong innerText
Chi phí
Khoảng 8 giây/trang, cần một tiến trình Chromium.
browser = p.chromium.launch(headless=True)
page = browser.new_page(locale="vi-VN")
page.goto("https://www.lazada.vn/dien-thoai-di-dong/?page=2", wait_until="domcontentloaded")
page.wait_for_timeout(7000)
items = page.eval_on_selector_all('[data-qa-locator="product-item"]',
    "els => els.map(e => ({id: e.dataset.itemId, title: e.querySelector('a[title]')?.title, text: e.innerText}))")

4Playwright + phiên đăng nhập thật (chỉ thử với Shopee)

Thư viện
chromium.launch_persistent_context(user_data_dir, headless=False)
Cách làm
Mở /buyer/login, người dùng tự đăng nhập; script polling page.url chờ rời trang login, sau đó vào trang tìm kiếm và danh mục để đọc DOM. Profile được lưu lại để giữ cookie phiên.
Mục đích
Phân biệt Shopee chặn vì "chưa đăng nhập" hay vì "phát hiện automation".

Kỹ thuật bổ trợ: đọc robots.txt, sitemap để khám phá URL sản phẩm, so sánh tập ID giữa các trang để kiểm tra phân trang. Không dùng: proxy xoay vòng, captcha solver, plugin stealth (che navigator.webdriver), giả User-Agent Googlebot. Các cách này là vượt anti-bot và vi phạm ToS.

3. Phân tích cơ chế chặn của Shopee

  • Client-side rendering: HTML chỉ là khung SPA. Dữ liệu tải qua XHR tới /api/v4/*.
  • Request signing: các XHR đó cần header ký số af-ac-enc-dat, x-sap-ri… do JavaScript đã obfuscate sinh ra. Thiếu header thì nhận 403, mã lỗi 90309999.
  • Bot fingerprinting: phát hiện automation qua navigator.webdriver = true, fingerprint của Chromium do Playwright điều khiển (thiếu plugin, profile trống…). Bị chặn từ bước đăng nhập nên có tài khoản thật cũng không qua.
  • Muốn vượt thì phải reverse-engineer thuật toán ký hoặc dùng stealth + proxy + captcha solver. Đó là vượt anti-bot, vi phạm ToS, có rủi ro khóa tài khoản, và dễ hỏng mỗi khi Shopee đổi script.
